The first call got 402 Payment Required with a price attached. Your test wallet paid 0.01 USDC, and the retry came back 200 with the data. That's the whole protocol: plain HTTP, plus a Transactions that settles in under a second.


Wallets & signaturesNew conceptLearn more →


A wallet is a keypair: a public address that anyone can pay, and a private key that signs approvals and never leaves the device.
Like:An account number plus a password that only ever approves things and never gets sent anywhere.


TransactionsNew conceptLearn more →


A transaction is a signed request to change the shared ledger. It either fully happens or doesn't happen at all, and once confirmed anyone can look it up.
Like:A signed, atomic database write with a public audit log.


Why 402?


HTTP has reserved status 402 “Payment Required” since 1997 without ever defining how to pay. x402 is the open standard that fills that gap: the 402 response lists accepted payments, and the client retries with an X-PAYMENT header containing a signed payment. On Solana that payment costs a fraction of a cent, which is what makes 1¢ prices work.

Design notes
Why this page looks the way it does. These are for reviewers, not part of the product. Full evidence and sources: Docs Research.


WhySame shape as the payments path: use it as a customer first. Here the “customer” is an HTTP client, so the developer sees raw requests and responses. That's the format web2 API developers already think in.
WhyWallet and transaction are introduced again, using the same text as the payments path. Each path is a possible entry point, so at most once per path means once in each path, not once across the site.
