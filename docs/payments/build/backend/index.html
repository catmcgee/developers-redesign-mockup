Confirm payments from your backend

Your server should ship the order only after it has checked the payment on the network itself. Run this from your own machine against devnet.

Copy MarkdownOpen ▾~10 min
STEP 1 ✓Pay as a customerSTEP 2 ✓ ★ first winBuild it in the browserSTEP 3Confirm from your backendSTEP 4Go live

1. Install the SDK

No CLI and no local network. One package and a URL:

npm install @solana/kit
echo 'RPC_URL=https://api.devnet.solana.com' >> .env.local
RPCNew conceptLearn more →
RPC is the HTTP/JSON API your code uses to read from and send to the network. Use public endpoints for testing and a provider in production.
Like:A hosted database endpoint, with RPC providers in the role of AWS or Supabase.

2. Add a verify endpoint

Given an order and the signature from the checkout, fetch the transaction from the network and check that it really paid you, in USDC, the right amount, for this order:

app/api/orders/[id]/confirm/route.ts
import { createSolanaRpc, signature as toSignature } from "@solana/kit";
import { findTransfer } from "./lib/payments"; // ~20 lines, see Verification tools

const rpc = createSolanaRpc(process.env.RPC_URL!);

export async function POST(req: Request, { params }) {
  const { signature } = await req.json();
  const order = await db.orders.get(params.id);

  const tx = await rpc.getTransaction(toSignature(signature), {
    commitment: "confirmed",          // see "Confirmation & finality" below
    encoding: "jsonParsed",
    maxSupportedTransactionVersion: 0,
  }).send();

  if (!tx || tx.meta?.err) return Response.json({ paid: false }, { status: 402 });

  const paid = findTransfer(tx, { to: STORE_USDC_ACCOUNT, mint: USDC_MINT, reference: order.reference });
  if (!paid || paid.amount !== order.totalUsdc) return Response.json({ paid: false }, { status: 402 });

  await db.orders.markPaidOnce(order.id, signature); // a signature can only pay once
  return Response.json({ paid: true });
}
import express from "express";
import { createSolanaRpc, signature as toSignature } from "@solana/kit";

const rpc = createSolanaRpc(process.env.RPC_URL);
const app = express().use(express.json());

app.post("/orders/:id/confirm", async (req, res) => {
  const order = await db.orders.get(req.params.id);
  const tx = await rpc.getTransaction(toSignature(req.body.signature), {
    commitment: "confirmed", encoding: "jsonParsed", maxSupportedTransactionVersion: 0,
  }).send();
  const paid = tx && !tx.meta?.err && findTransfer(tx, { to: STORE_USDC_ACCOUNT, mint: USDC_MINT, reference: order.reference });
  if (!paid || paid.amount !== order.totalUsdc) return res.status(402).json({ paid: false });
  await db.orders.markPaidOnce(order.id, req.body.signature);
  res.json({ paid: true });
});
from solana.rpc.api import Client
from solders.signature import Signature

rpc = Client(os.environ["RPC_URL"])

def confirm(order_id: str, signature: str) -> bool:
    order = db.orders.get(order_id)
    tx = rpc.get_transaction(Signature.from_string(signature), "jsonParsed",
                             commitment="confirmed", max_supported_transaction_version=0).value
    if tx is None or tx.transaction.meta.err:
        return False
    paid = find_transfer(tx, to=STORE_USDC_ACCOUNT, mint=USDC_MINT, reference=order.reference)
    if not paid or paid.amount != order.total_usdc:
        return False
    return db.orders.mark_paid_once(order.id, signature)  # a signature can only pay once
Confirmation & finalityNew conceptLearn more →
A transaction goes from processed to confirmed (~0.4 s) to finalized. Confirmed is enough for most orders. Finalized can't be reversed, and takes longer.
Like:Pending → authorized → settled.

3. Call it from the checkout

checkout.tsx
onPaymentSuccess={async (signature) => {
  const r = await fetch("/api/orders/" + order.id + "/confirm", {
    method: "POST", body: JSON.stringify({ signature }),
  });
  if ((await r.json()).paid) router.push("/thanks");
}}

4. Test it

Pay with your test wallet from the previous step, then call the endpoint directly with that signature:

curl -X POST localhost:3000/api/orders/demo/confirm \
  -d '{"signature":"<your signature from step 2>"}'
# {"paid":true}

Want the CLI, a local test network or Anchor? You don't need them for payments, but Set up your machine covers them.

Design notes

Why this page looks the way it does. These are for reviewers, not part of the product.

WhyStage 5 of the template, plug it into your stack. It runs on the developer's machine in their framework, and it carries the path's real engineering lesson: never trust the client, verify on the network. That's the step MLH participants said was missing (“examples ended with no next step”).
WhyRPC and confirmation levels are introduced here because this is the first time they matter. Taught before step 2 they would have been noise.
Vs. todayInstallation (CLI, Anchor, Surfpool) is currently Getting Started → Installation. Here it's an optional link, because payments only need npm install and a URL.
Risk / dependencyThe code is illustrative. The pilot needs a real, tested findTransfer helper (or a Commerce Kit server helper), so developers don't hand-parse transactions.
