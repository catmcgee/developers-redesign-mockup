Transactions

In shortsame text as in the paths
A transaction is a signed request to change the shared ledger. It either fully happens or doesn't happen at all, and once confirmed anyone can look it up.
Like:A signed, atomic database write with a public audit log.

What's in a transaction

A transaction bundles one or more instructions, each one a call to a program, plus the list of accounts those instructions read or write, a recent blockhash, and the signatures of every account that has to approve.

PartWhat it isIn the payments path
SignaturesOne per required signer; the first is the transaction IDYour test wallet's approval
InstructionsProgram calls, run in orderOne Token program transfer
AccountsEvery account read or writtenYour USDC account, the shop's
Recent blockhashProves it's fresh; expires after ~60–90 sWhy retries rebuild the transaction

All or nothing

If any instruction fails, the whole transaction fails and no state changes. That's why the blocked transfer in the tokenization path left your balance untouched.

Size and expiry

Transactions are limited to 1,232 bytes and must land before their blockhash expires. In practice: keep them small, and when a send times out, rebuild with a fresh blockhash instead of resending forever.

Fees

Every transaction pays a base fee per signature, plus an optional priority fee when the network is busy. See Fees.
