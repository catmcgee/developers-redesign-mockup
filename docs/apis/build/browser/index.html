Paywall an endpoint in your browser

One middleware, a price and your wallet address. Run it, and a test client pays for each request.

Test client · devnet
The test client calls your endpoint without paying, reads the price from the 402, signs a payment with its own keypair, and retries.
Your endpoint just got paid.Change the price or route and run it again. Next, put it in your real server.

What the code is doing

  • The first argument is your wallet address: where payments land.
  • The route map sets a price per endpoint. Requests without a valid payment get a 402 listing that price.
  • The facilitator checks the client's signed payment, submits it, and confirms it, so your server doesn't need to talk to the network itself.

The test client is a script with its own keypair, which is a wallet in code. That's how AI agents pay: they hold a wallet with a spending limit you set. See Agents that pay.

Add it to your server

Install the middleware in your own app, choose a facilitator, and call it from a real client.

Design notes

Why this page looks the way it does. These are for reviewers, not part of the product.

WhyThe first success is the server side, because that's the developer's job here. The client is simulated so that nothing has to be installed.
Risk / dependencyThis needs a hosted devnet demo endpoint and facilitator owned by the docs team. A third-party demo that disappears would break the path. The middleware API shown is illustrative and must match the SDK at launch.
